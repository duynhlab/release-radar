OPS RELEASE RADAR
Personal DevOps/SRE Release Tracker
===================================

1. MỤC TIÊU
-----------

Xây dựng một dự án nhỏ phục vụ cá nhân để:

- Theo dõi phiên bản mới của các công cụ DevOps/SRE trên GitHub.
- Tự động kiểm tra release mới mỗi ngày.
- Phân loại công cụ theo Platform, Provisioning, Delivery, Observability...
- Hiển thị các release mới theo ngày, tuần và từng nhóm công cụ.
- Lưu lịch sử release để có thể tra cứu lại.
- Deploy website bằng Next.js lên Cloudflare.

Tên repository đề xuất:

    ops-release-radar

Một số tên khác:

- devops-release-catalog
- ops-radar
- duyops-radar


2. Ý TƯỞNG HỌC TỪ FLUX-SCHEMA
-----------------------------

Không cần sao chép toàn bộ codebase của fluxcd/flux-schema.

Điểm nên học từ dự án này là mô hình:

    Catalog khai báo trong Git
             |
             v
    Workflow chạy định kỳ
             |
             v
    Thu thập dữ liệu upstream
             |
             v
    Sinh dữ liệu chuẩn hóa
             |
             v
    Commit hoặc tạo Pull Request

flux-schema sử dụng catalog và GitHub Actions để định kỳ lấy các phiên bản
upstream, sinh lại schema và tạo Pull Request cập nhật.

Tham khảo:
https://github.com/fluxcd/flux-schema
https://github.com/fluxcd/flux-schema/blob/main/.github/workflows/update-catalog.yaml

Đối với Ops Release Radar, phần cần lấy từ upstream là GitHub Releases thay vì
Kubernetes JSON Schema.


3. KIẾN TRÚC MVP
----------------

    config/tools.yaml
    Danh sách tool cần theo dõi
             |
             v
    GitHub Actions - chạy mỗi sáng
             |
             v
    GitHub Releases API
             |
             v
    data/releases/*.json
    Dữ liệu đã chuẩn hóa và có lịch sử
             |
             v
    Next.js application
             |
             v
    Cloudflare Workers

Khuyến nghị trong MVP:

- Không dùng database.
- Không gọi GitHub API trực tiếp khi người dùng mở website.
- GitHub Actions chịu trách nhiệm lấy và chuẩn hóa release.
- Dữ liệu release được commit trở lại repository.
- Next.js đọc JSON đã được sinh sẵn.
- Cloudflare tự build lại khi repository có commit mới.

Lợi ích:

- Có Git history và diff rõ ràng.
- Không lộ GitHub token ở frontend.
- Website không phụ thuộc GitHub API tại runtime.
- Không gặp rate limit khi người dùng truy cập website.
- Có thể fork, backup hoặc migrate dễ dàng.
- Không phải quản lý database trong giai đoạn đầu.

5. CATALOG KHAI BÁO TOOL
------------------------

File:

    config/tools.yaml

Ví dụ:

    schemaVersion: 1

    tools:
      - id: flux
        name: Flux
        category: delivery
        repository: fluxcd/flux2
        description: GitOps toolkit for Kubernetes
        homepage: https://fluxcd.io
        tags:
          - gitops
          - kubernetes
        release:
          strategy: github-releases
          includePrerelease: false
          tagPattern: "^v\\d+\\.\\d+\\.\\d+$"

      - id: otel-collector
        name: OpenTelemetry Collector
        category: observability
        repository: open-telemetry/opentelemetry-collector-releases
        description: Vendor-neutral telemetry collector
        tags:
          - metrics
          - logs
          - traces
        release:
          strategy: github-releases
          includePrerelease: false

Các release strategy nên hỗ trợ:

1. github-releases

   Dùng cho repository có phát hành GitHub Release đầy đủ.

2. github-tags

   Dùng làm fallback cho repository chỉ tạo Git tag nhưng không tạo Release.

3. manual

   Dùng cho công cụ không phát hành qua GitHub hoặc cần quản lý đặc biệt.

Các field nên có:

- id
- name
- category
- repository
- description
- homepage
- documentation
- tags
- release.strategy
- release.includePrerelease
- release.tagPattern
- release.ignorePattern
- enabled

7. LOGIC ĐỒNG BỘ RELEASE
------------------------

Không nên chỉ gọi:

    GET /repos/{owner}/{repo}/releases/latest

Lý do:

- Endpoint latest bỏ qua draft và prerelease.
- GitHub xác định latest dựa trên created_at.
- created_at có thể không phản ánh đúng thời điểm release được publish.
- Một project có thể phát hành nhiều release giữa hai lần đồng bộ.

Logic đề xuất:

1. Đọc và validate config/tools.yaml.
2. Lấy khoảng 10 release gần nhất của từng repository.
3. Bỏ draft.
4. Bỏ prerelease nếu includePrerelease là false.
5. Áp dụng tagPattern và ignorePattern.
6. Sắp xếp theo published_at.
7. Merge release dựa trên GitHub release ID.
8. Không tạo release trùng.
9. Giữ tối đa 20 release cho mỗi tool.
10. Sinh lại data/index.json.
11. Nếu dữ liệu không đổi thì không commit.
12. Nếu có thay đổi thì commit vào repository.

Commit message đề xuất:

    chore(data): sync releases 2026-07-29

GitHub Releases API:
https://docs.github.com/en/rest/releases/releases


8. GITHUB ACTIONS
-----------------

Workflow:

    .github/workflows/sync-releases.yaml

Nên hỗ trợ:

- Chạy theo schedule.
- Cho phép chạy thủ công bằng workflow_dispatch.
- Chỉ cấp permissions cần thiết.
- Có concurrency để không chạy hai job sync cùng lúc.
- Có timeout.
- Không commit nếu dữ liệu không thay đổi.

Thời gian đề xuất:

    07:17 Asia/Ho_Chi_Minh mỗi ngày

Không nên chạy đúng phút 00 vì GitHub cảnh báo scheduled workflow có thể bị
delay trong thời gian tải cao, đặc biệt ở đầu mỗi giờ.

Pseudo workflow:

    name: Sync releases

    on:
      workflow_dispatch:
      schedule:
        - cron: "17 7 * * *"
          timezone: "Asia/Ho_Chi_Minh"

    permissions:
      contents: write

    concurrency:
      group: sync-releases
      cancel-in-progress: false

    jobs:
      sync:
        runs-on: ubuntu-latest
        timeout-minutes: 15

        steps:
          - Checkout repository
          - Setup pnpm
          - Setup Node.js
          - Install dependencies
          - Validate tool catalog
          - Sync GitHub releases
          - Run generated-data validation
          - Commit and push if changed

GitHub schedule documentation:
https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

GitHub REST API rate limit:
https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api

GITHUB_TOKEN hiện có giới hạn 1.000 REST request/giờ cho mỗi repository, đủ cho
MVP theo dõi khoảng 30 đến 100 tool.

12. CLOUDFLARE DEPLOYMENT
-------------------------

Next.js được deploy lên Cloudflare Workers thông qua OpenNext adapter.

Cloudflare hiện hỗ trợ phần lớn tính năng Next.js cần thiết:

- App Router
- React Server Components
- Static Site Generation
- Server-Side Rendering
- Incremental Static Regeneration
- Route Handlers
- Server Actions

Đối với dự án này, phần lớn trang có thể được render tĩnh từ generated JSON.

Deployment flow đề xuất:

    GitHub Action sync release
              |
              v
    Commit dữ liệu mới vào main
              |
              v
    Cloudflare Git integration phát hiện commit
              |
              v
    Build Next.js
              |
              v
    Deploy Cloudflare Workers

Không nên cấu hình đồng thời:

- Cloudflare Git integration; và
- Một GitHub Actions workflow khác cũng deploy Cloudflare.

Chỉ chọn một deployment path để tránh double build và double deploy.

Khuyến nghị dùng Cloudflare Git integration vì đơn giản hơn cho dự án cá nhân.

Nếu website chỉ dành cho cá nhân:

- Đặt Cloudflare Access phía trước website.
- Không cần tự xây authentication trong Next.js.


13. CI WORKFLOW
---------------

Workflow:

    .github/workflows/ci.yaml

Chạy khi:

- Pull request vào main.
- Push vào main, ngoại trừ commit chỉ thay đổi generated data nếu muốn giảm CI.

Các bước:

1. Install dependencies.
2. Validate tools.yaml.
3. Lint.
4. Type check.
5. Unit test.
6. Next.js build.
7. Cloudflare preview build bằng workerd nếu cần.

Security cơ bản:

- Chỉ cấp contents: read cho CI.
- Sync workflow mới có contents: write.
- Pin các GitHub Actions quan trọng bằng commit SHA.
- Không ghi GitHub token vào file hoặc log.
- Sanitize release notes trước khi render.

KẾT LUẬN
--------

Ops Release Radar nên được xây như một Git-backed release catalog:

- Catalog tool quản lý bằng YAML.
- GitHub Actions cập nhật release mỗi ngày.
- Release history được lưu thành JSON trong repository.
- Next.js chỉ đọc dữ liệu đã chuẩn hóa.
- Cloudflare Workers chịu trách nhiệm phục vụ website.

Thiết kế này đủ nhỏ để phục vụ cá nhân nhưng vẫn có cấu trúc rõ ràng để sau này
mở rộng thêm notification, EOL, CVE và installed-version tracking.
